# libfcp v1.0.0-rc.1

This is the first public release candidate for Federated CFR Connect Protocol.
It is suitable for integration work and independent review. It is not yet a
final API, wire-format or deployment-stability promise.

## Packages

| package | role | Rust support |
|---|---|---|
| `libfcp-core` | portable FCP grammar, mandatory dual-signature configuration and state machine | 1.85, `no_std + alloc` |
| `libfcp` | member SDK, CFR routing and transport contract | 1.85 |
| `libfcp-server` | in-process signed configuration authority | 1.85 |
| `libfcp-webrtc` | optional real Rust/Tokio WebRTC.rs adapter | 1.98+ |

## Included behavior

The RC includes canonical `FCP` signaling envelopes, complete endpoint and
authority identities authenticated by both Ed25519 and ML-DSA-65, signed `FCFG`
federation configuration snapshots, bounded replay/state/input controls, explicit
CFR-to-FCP routing, a fixed reliable ordered control channel, hostile-signaling
rejection, backpressured application queues, typed graceful close, and a real
localhost ICE → DTLS → SCTP → DataChannel integration test.

## Compatibility boundary

The `FCP` marker and current wire version identify this release-candidate
protocol. Changes to public API, configuration artifact, or wire behavior may
occur before a stable release. Applications should pin exact package versions and
retain the complete authority identity, accepted configuration epoch, and
peer-attempt retry policy in their own persistent control plane.

## Validation scope

The release gate includes portable Rust 1.85 tests and strict Clippy, Android
AArch64/iOS AArch64/WASM `no_std` checks, stable Rust concrete-adapter tests and
strict Clippy, plus a clean-room archive build resolving published
`cfr_protocol v1.0.0-rc.1` from crates.io. CI repeats those relevant gates on
push and pull request; supply-chain workflows audit advisories and dependency
policy.

## Not included

The portable package set listed above does not provide hosted signaling, TURN
deployment, identity bootstrap, browser adapters, JNI/Swift bindings, real
public-NAT interoperability certification, a device matrix, an external
cryptographic audit, generic authority-server CLI or end-to-end post-quantum
transport authentication. The optional FCP Fabric platform is documented
separately in [`../fabric/README.md`](../fabric/README.md). FCP configuration
and signaling require Ed25519 plus ML-DSA-65 signatures; the current WebRTC DTLS
path is not post-quantum. The RustCrypto `ml-dsa` dependency is not independently
audited by this project. See [`../security.md`](../security.md) and
[`../operations.md`](../operations.md).

## Publication order

The package dependencies require this crates.io order:

```text
libfcp-core → libfcp-server → libfcp → libfcp-webrtc
```

After each prerequisite appears in the crates.io index, the next package is
isolated-packaged and verified. The protected manual release workflow requires
the `PUBLISH-LIBFCP` confirmation and does not create a Git tag or GitHub
release.
